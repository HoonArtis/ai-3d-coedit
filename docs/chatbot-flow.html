AI 도우미 사용자 흐름

학생이 오른쪽 패널에 한 줄을 보내면 무슨 일이 생기는지, 그리고 챗봇이 그 한 줄을 무엇으로 바꿀 수 있는지(도구 25개)를 정리했습니다. 모델은 로컬 qwen3:4b 하나입니다. 챗봇은 도구와 인자만 고르고, 실제 변경은 기즈모와 같은 명령 경로를 거칩니다.

학생 도구 25강사 전용(제외) 5평가 문항이 있는 도구 17/25마지막 평가 19/20 (10/13)

네 단계는 모든 요청이 같고, 모델의 결정에 따라 아래 여섯 갈래 중 하나로 끝납니다. 점선 원은 학생이 직접 하는 단계입니다.

contracts/chat.ts
모델이 낸 결정에 따라 갈라짐

A. 바로 실행

ops = 편집·배치 도구
  1. ops 전체를 명령 1건으로 제출
  2. 배치 도구는 서버 코드가 좌표를 계산해 풀어 씀
  3. 권한 → 잠금 → 순번 판정, 하나라도 실패하면 전부 롤백
화면summary + "완료했어요." + 방금 거 취소실패하면 summary 대신 서버 오류 문구

B. 조회

ops = list · find · describe_scene
  1. 씬은 바뀌지 않음
  2. 서버가 물체 목록을 돌려줌 (find는 이름 포함 검색)
화면"의자 · 위치 1, 0, 3" 형식 목록없으면 "조건에 맞는 에셋이 없어요."

C. 되묻기

clarification 있음, ops = []
  1. "저거 지워"인데 선택이 없을 때 등
  2. 학생이 에셋을 고르고 다시 보냄
  3. 두 번째에도 모호하면 질문 대신 "대상을 선택한 뒤 다시 요청해 주세요."
화면"어떤 에셋을 삭제할까요?"

D. 거절

clarification 없음, ops = []
  1. 남의 에셋 수정, 강사 권한, 부적절한 생성 요청
  2. summary로 이유만 알려 줌
화면"다른 학생의 에셋은 삭제할 수 없어요."

모델이 놓쳐도 A의 서버 권한 검사가 막습니다. 평가의 유일한 오답이 이 경우였습니다.

E. 생성으로 넘김

ops = generate · retexture (단독)
  1. 금칙어 필터 → GPU 큐에 이미지 작업 등록
  2. 학생은 생성 패널에서 이미지 확인
  3. 3D·텍스처 → History → place로 배치
화면채팅에는 바로 "완료했어요."

다른 편집과 섞으면 "생성 요청은 다른 편집과 나눠서 보내 주세요."

F. 처리 실패

모델·큐·서버 오류
  1. 120초 초과, 모델 응답 깨짐, Ollama 꺼짐
  2. 대기 중에 강사가 작품을 복원함 (SCENE_RESTORED)
화면"처리하지 못했어요. MODEL_TIMEOUT"

오류 코드가 그대로 학생에게 보입니다.

챗봇이 고를 수 있는 도구

명령 계약의 op 30개 중 강사 전용 5개를 뺀 25개를 도구 정의로 넘깁니다. 기존 평가 문서에는 24개로 적혀 있지만 실제 studentTools.length는 25입니다. 인자 이름은 실제 스키마 그대로입니다. 예시 문장은 tools.ts의 도구 설명에 들어가는 것입니다.

평가20문항 평가에 포함평가 없음측정한 적 없음단독다른 op와 섞을 수 없음주의아래 관찰 참고

흐름을 그리며 보인 것

코드를 읽고 확인한 것이며, 실제 화면으로 재현하지는 않았습니다.

1

생성 요청도 "완료했어요"로 끝남

E 갈래는 큐 등록만 하고 ok:true, changedIds:[]를 돌려줍니다. ChatPanel은 ok면 무조건 "완료했어요."를 띄우므로, 학생은 아직 그림도 나오지 않았는데 끝났다고 읽게 됩니다. "생성 패널에서 확인해 주세요"로 바꿀 자리입니다.

2

describe_scene이 list와 똑같음

apply-command.ts에서 두 op 모두 전체 물체 목록을 돌려줍니다. "공간에 뭐가 있어"에 문장 설명이 나오지 않습니다. 또 list 예시가 "내가 놓은 거 뭐 있어"인데 결과는 남의 것까지 포함됩니다.

3

챗봇이 방금 한 일을 모름

대화 이력에는 학생 문장과 summary만 들어가고 실제 ops·생성된 ID·결과는 빠집니다. "방금 놓은 의자 돌려줘"처럼 이어지는 요청은 선택에 기대야 합니다.

4

평가가 없는 도구 8개

scatter, list, lock, unlock, generate, retexture, upload_character, replace_asset은 20문항에 없습니다. list는 describe_scene과 같은 경로라 사실상 확인된 셈이고, 나머지 7개는 측정한 적이 없습니다. 특히 학생이 자주 쓸 generate는 문장을 어떻게 옮기는지 측정한 적이 없습니다.

5

오류 코드가 학생 화면에 그대로 나옴

F 갈래는 MODEL_TIMEOUT 같은 내부 코드를 붙여 보여 줍니다. 생성 쪽은 generationMessage로 한국어 문구를 쓰는 것과 다릅니다.
