# 모듈 경계와 주기적 검증

필수 규칙 원본: [CLAUDE.md](../../CLAUDE.md#작업-중-필수-검증-모듈화). 실행 플랜: [PLAN.md](PLAN.md).

## 의존 방향

| 모듈 | 책임 | 허용 연결 |
|---|---|---|
| contracts | op·이벤트·오류·예산·런타임 입력 검증 | 앱/도메인 의존 없음 |
| domain | 권한·명령의 순수 판정 및 상태 전이 | contracts |
| placement | 좌표·겹침·정렬 계산 | contracts |
| web | UI·개인 카메라·표시·명령 전송 | contracts, 공개 네트워크 transport; 테스트 transport만 domain |
| server | 인증·잠금·seq·내구 저장 조정·방송 | contracts, domain, placement, 저장/큐 adapter |
| llm | 모델 호출·프롬프트·도구 선택 | contracts, 서버 명령 client, 모델 adapter |
| workers | 큐 작업·외부 워커 통신 | contracts, 공개 작업 API |
| gpu | 형상·텍스처·감량·VR 굽기 | 버전 있는 작업 JSON 및 adapter; 웹/방 상태 직접 변경 금지 |

서버 저장 구현·모델 구현·GPU 라이브러리는 각 adapter 내부에만 둔다. 초기 디렉터리 부재는 정상이다. CORE-03에서 실제 import 검사로 이 표를 구현한다. 배치 결과는 서버가 검증하며 LLM과 클라이언트가 권한/잠금 규칙을 별도 구현하지 않는다.

## 검증 주기

1. 티켓 시작 전: 변경 파일의 책임, 공개 입력·출력, 선행 계약을 확인한다.
2. 티켓 완료 전: CLAUDE.md의 5개 항목을 코드·테스트 근거와 함께 티켓에 기록한다.
3. 태스크 완료 시: 개별 티켓을 넘어 전체 의존 그래프와 소비자 통합을 확인한다.
4. 공용 API·DB 스키마·모듈 의존 변경 직후: 소비 모듈 테스트를 즉시 재실행한다.

CORE-03-03 이후 `npm run check:modules`를 실행한다. 정적 검사만으로 책임 분리와 중복을 입증할 수 없으므로 변경 diff 수동 검토도 기록한다. 위반 수정과 재검증이 끝나지 않으면 done으로 바꾸지 않는다. 이 규칙은 모듈별 테스트와 실제 기기 검증을 대체하지 않는다.

모듈화 검증 실패도 [WORKFLOW.md](WORKFLOW.md)의 수정·재검증 루프를 따른다. 같은 문제의 수정·재검증이 2회 연속 실패하면 기존 구조·커밋·공식 해결 사례를 조사하고, 근거 없이 파일 이동이나 추측 리팩터링을 반복하지 않는다. 출처·수정·소비 모듈 회귀 결과를 해당 실행 티켓에 기록한다.
