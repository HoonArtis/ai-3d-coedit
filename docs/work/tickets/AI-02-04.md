**이번 티켓의 결과: 20문항 모델 평가·선정.** 아래 정상·실패 조건에 필요한 부분만 구현한다. 같은 작업 묶음의 다른 동작은 형제 티켓에서 처리한다.

## 구현 위치와 계약

아래는 담당 모듈의 후보 파일이다. 착수 시 이번 동작에 필요한 파일만 실행 기록에 확정한다. 작업 묶음 전체를 이 티켓에서 구현하지 않는다.

- `apps/llm/src/model-port.ts`
- `apps/llm/src/tools.ts`
- `apps/llm/prompts/student.md`
- `tests/llm/tools.test.ts`
- `docs/evidence/llm-evaluation.md`
- 이번 티켓의 검증 파일/증거: `tests/tickets/ai-02-04.test.ts`

공개 계약 원본(필요한 부분만 소비·구현):

`ModelPort.chooseTools(messages, scene): Promise<ToolCall[]>; tools는 contracts의 op에서 파생`

선행 티켓이 제공한 타입과 공개 API를 사용한다. 명시한 축약형 인자의 세부 스키마는 CORE-01의 contracts에서 정의·검증하고, 소비 모듈 안에서 비슷한 타입을 다시 만들지 않는다.

새 필드·내부 모듈·검증 파일이 필요하면 원본 contracts와 이 티켓에 함께 기록한다. 공개 계약 변경 직후 소비 모듈을 재검증한다.

## 검증 기준

| 검사 | 입력·상황과 기대 결과 |
|---|---|
| 정상 동작 | 동일 한국어 20문항에서 도구·인자 정확도와 지연을 로컬/차선에 대해 기록한다 |
| 실패·경계 동작 | 실패 문항을 제외해 성공률을 높이지 않고 사용 불가능한 모델은 미검증으로 표시한다 |
| 회귀 | 이번 변경의 직접 소비자와 선행 계약 테스트가 기존 기대 결과를 유지한다. 선택한 테스트와 이유를 실행 기록에 적는다. |

예정 검증: `npx vitest run tests/tickets/ai-02-04.test.ts; 실제 모델/장치/서비스 실행 증거도 기록한다. mock 통과만으로 완료하지 않는다.`

테스트 이름은 `test_ai_02_04_success`, `test_ai_02_04_failure`로 구분하고 위 표의 결과를 실제 assertion으로 고정한다. 도구 설치·fixture·세부 인자는 선행 계약을 따른다. 이 명령은 계획이며 아직 실행하지 않았다. 조사/실측은 테스트 코드를 억지로 만들지 않고 조건별 원문/측정 증거로 검증한다.

## 구현 → 검증 → 수정 → 재검증

- [x] **준비:** 선행 완료·외부 조건, 수정 파일, 책임, 입력/출력을 확인한다.
- [x] **재현 기준:** 위 정상·실패 조건을 테스트/실험으로 고정한다. 구현 전 의도한 RED는 수정 실패 횟수에 포함하지 않는다.
- [x] **구현:** 단일 결과를 구현하고 현재 단계를 `검증`으로 바꾼다.
- [x] **검증:** 예정 검증을 실제 실행해 출력·환경·증거를 기록한다. 실패하면 아래 수정 루프로 들어간다.
- [x] **원인 확인·수정:** 실패 입력·오류·원인 가설·변경을 한 회차씩 기록한다. 같은 증상에서 검증 없이 변경을 쌓지 않는다.
- [x] **재검증:** 수정 후 같은 실패 재현과 정상 테스트를 다시 실행한다. 실패하면 회차를 증가시키고 `수정` 단계로 돌아간다.
- [x] **회귀·모듈화:** 직접 영향받는 소비자 테스트 및 아래 모듈화 검증을 실행한다. 실패하면 다시 수정한다.
- [x] **완료 판정:** 정상·실패 조건 및 회귀·모듈화가 모두 통과하고 미해결 결함이 없을 때만 `done`으로 바꾼다.

결함이 처음부터 없으면 수정·재검증 항목은 `해당 없음 — 최초 검증 통과 증거`로 기록한다. 빈 체크박스를 남긴 채 done 처리하지 않는다. 외부 조건이 없으면 실제 통합 검증을 통과했다고 적지 않는다.

## 2회 실패 시 해결 사례 조사 (필수)

같은 문제의 **수정·재검증이 2회 연속 실패하면** 독자적인 추측 수정을 멈추고 현재 단계를 `사례 조사`로 전환한다. 작업/도구/명령 이름을 바꿔 실패 횟수를 초기화하지 않는다.

- [x] 저장소 코드·git log·기존 티켓 실패 기록에서 같은 증상의 해결 이력을 찾는다.
- [x] 공식 문서·릴리스 노트·공식 이슈/PR을 검색한다. 필요하면 허용된 페이지 수집/크롤링, 다른 검색 도구로 근거를 확보한다.
- [x] 출처의 버전·OS·런타임·증상을 현재 환경과 비교하고 적용 가능/불가 사유를 기록한다.
- [x] 채택할 해결법 또는 최소 재현·계측·버전 비교·대체 도구의 실험을 한 가지씩 정해 실행한다.
- [x] 동일 실패 재현 + 정상 + 영향 회귀를 재실행하고 아래 기록을 갱신한다.

2회 실패가 발생하지 않았으면 이 분기는 `미발동 — 회차 기록 참조`로 남긴다. 근거를 찾지 못하면 검색어·조사 범위·대안 실험을 기록한다. 증거 없이 또 추측 수정하지 않는다. 외부 조건 때문에 더 진행할 수 없으면 차단 원인과 해제 조건을 적고 독립 티켓을 진행한다.
