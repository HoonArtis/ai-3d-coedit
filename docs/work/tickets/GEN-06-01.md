## 구현 위치와 계약

아래는 담당 모듈의 후보 파일이다. 착수 시 이번 동작에 필요한 파일만 실행 기록에 확정한다. 작업 묶음 전체를 이 티켓에서 구현하지 않는다.

- `workers/gpu/pipeline/character.py`
- `apps/web/src/characters/Upload.tsx`
- `workers/gpu/tests/test_character.py`
- 이번 티켓의 검증 파일/증거: `workers/gpu/tests/test_gen_06_01.py`

공개 계약 원본(필요한 부분만 소비·구현):

`convertCharacter(upload): CharacterManifest`

선행 티켓이 제공한 타입과 공개 API를 사용한다. 명시한 축약형 인자의 세부 스키마는 CORE-01의 contracts에서 정의·검증하고, 소비 모듈 안에서 비슷한 타입을 다시 만들지 않는다.

새 필드·내부 모듈·검증 파일이 필요하면 원본 contracts와 이 티켓에 함께 기록한다. 공개 계약 변경 직후 소비 모듈을 재검증한다.

## 검증 기준

| 검사 | 입력·상황과 기대 결과 |
|---|---|
| 정상 동작 | 허용 FBX를 GLB로 변환하고 파일 크기/형식을 검사한다 |
| 실패·경계 동작 | 과대·손상 파일을 거부하며 변환 오류 시 기본 캐릭터로 안내한다 |
| 회귀 | 이번 변경의 직접 소비자와 선행 계약 테스트가 기존 기대 결과를 유지한다. 선택한 테스트와 이유를 실행 기록에 적는다. |

예정 검증: `py -m pytest workers/gpu/tests/test_gen_06_01.py`

테스트 이름은 `test_gen_06_01_success`, `test_gen_06_01_failure`로 구분하고 위 표의 결과를 실제 assertion으로 고정한다. 도구 설치·fixture·세부 인자는 선행 계약을 따른다. 이 명령은 계획이며 아직 실행하지 않았다. 조사/실측은 테스트 코드를 억지로 만들지 않고 조건별 원문/측정 증거로 검증한다.

- [x] **구현:** 단일 결과를 구현하고 현재 단계를 `검증`으로 바꾼다.

결함이 처음부터 없으면 수정·재검증 항목은 `해당 없음 — 최초 검증 통과 증거`로 기록한다. 빈 체크박스를 남긴 채 done 처리하지 않는다. 외부 조건이 없으면 실제 통합 검증을 통과했다고 적지 않는다.

## 진행 기록 — 2026-10-14

자체 절차 생성한 2관절/Idle FBX와 GLB로 격리 Blender5.1.2 변환을 검증한다. 첫 검증에서 FBX의 static getBounds는 스킨 inverse-bind를 무시해 높이가 잘못 계산됐고, GLB는 importer의 관절 표시용 Icosphere를 미리깅 메시로 판정했다. 첫 수정의 object.hide_render 필터는 collection의 hide_render를 반영하지 못해 같은 GLB 문제가 2회 실패했다. 추측 수정을 멈추고 설치된 공식 io_scene_gltf2/blender/imp/node.py:151~169와 공식 API https://docs.blender.org/api/current/bpy.ops.import_scene.html 을 조사했다. 원본은 disable_bone_shape=True일 때 관절 표시 메시를 만들지 않고 반환한다. 이 공식 옵션을 적용해 재검증한다. 웹 도구의 문서 fetch는402였고 로컬 배포 소스를 근거로 삼았다. FBX 재검증은 별개로 deprecated Document.clone 사용 오류이며 설치 API가 제시하는 cloneDocument로 고친다.

GLB 높이1.202m 문제는 static bounds→스킨 실제 정점 계산 후에도 남고 Decimate를 Armature 앞에 적용한 수정도 동일해 2회 실패로 별도 조사했다. Blender에 import한 포즈의 실제 evaluated 높이는1.700m였으므로 정규화 입력보다 export의 rest pose 차이가 원인 후보다. 공식 glTF manual https://docs.blender.org/manual/en/5.4/addons/scene_gltf2.html 은 export_rest_position_armature=False가 현재 프레임 포즈를 joint rest pose로 사용한다고 명시한다. 설치5.1 exporter에도 같은 공개 옵션이 존재한다. 이를 명시해 import된 포즈를 보존하는 실험을 수행한다. 관련 구형 issue https://github.com/KhronosGroup/glTF-Blender-IO/issues/368 은 스킨 메시 변환 무시 규칙을 설명하지만 현재 버전에 그대로 적용하지 않는다.

현재 포즈 export 옵션은 높이 문제를 해결하지 못했다. 최소 재현에서 FBX는 desktop/avatar/VR 모두1.7m인데 GLB는 감량률에 따라1.20/1.50/.94m로 달라져 스킨 행렬보다 분리된 정점의 감량 손실로 원인 후보를 좁혔다. 공식 importer __init__.py의 merge_vertices 설명과 mesh.py를 확인: glTF는 flat normal/UV 경계마다 정점을 분리하며 기본값은 병합하지 않는다. 내장 merge_vertices도 다른 normal은 합치지 못한다. bind 위치와 joint-weight 튜플이 동일한 정점만 BMesh weld하고 UV는 loop에 유지한 뒤 감량하는 방법을 검증한다. 다른 관절 가중치 정점을 임의로 병합하지 않는다.
