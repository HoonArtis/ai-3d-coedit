# 개인 에셋 History · 수업 공유 — 2026-10-14

## 최신 동작

사용자 요청으로 강사 승인 절차를 제거했다. 형상/텍스처/감량 결과를 검증한 뒤 자동 등록한다. 새 생성물은 만든 학생 개인 소유이며 강사는 같은 수업의 개인 생성물을 확인하고 사용할 수 있다. 학생 간에는 History의 **수업에 공유**를 눌러 공개한 에셋만 배치할 수 있다. 다른 수업으로는 공유되지 않는다. 이전에 이미 승인·공유된 에셋은 기존 접근을 유지한다.

왼쪽 **History · 만든 에셋** → 학생은 **내 에셋**, 강사는 **학생 에셋**에서 3D 미리보기·배치·수업 공유를 할 수 있다. 다른 조에서는 **수업 공유** 탭에 제작 조 이름과 함께 나타난다. 원본 복사/수정 권한을 넘기는 방식이 아니라 에셋을 공유하며, 새 배치물의 소유자는 배치한 사람이다. 공유 해제와 History 원본 3D 삭제는 아직 제공하지 않는다.

장면 삭제는 오른쪽 속성의 삭제 버튼 또는 **Delete** 키로 한다. 입력창·contenteditable·선택 입력·모달·한글 조합 중에는 단축키 삭제를 보내지 않는다. 삭제와 Ctrl+Z 복원은 기존 서버 명령/잠금/저장/이력 경로를 그대로 사용한다. 장면 삭제로 History의 원본은 지우지 않는다.

## 검증·수정 이력

- 개인 완료 → 자동 등록 → 제작자/강사 접근, 다른 학생·다른 수업 거부, 공유 후 다른 조 접근, 중복 공유, 불량 산출물 거부와 횟수 반환을 PostgreSQL 통합 검증했다.
- 비공개 ID를 알아도 place/replace/duplicate 명령은 서버에서 거부한다. 이미 방에 놓인 개인 에셋은 동료에게 렌더링에 필요한 정의/파일만 제공하며 라이브러리 재사용 권한은 부여하지 않는다.
- History는 현재 편집기 세션 토큰을 사용한다. 최초 브라우저 검사에서 전역 계정 토큰을 읽던 문제가 드러나 수정했고, 다른 계정의 오래된 토큰을 쓰지 않는 회귀 테스트를 추가했다.
- 사용자 정의 에셋의 creator/shared 계약 변경 후 CPU·LLM 워커도 재시작했다. 이전 CPU 프로세스가 새 필드를 거부한 VR 실패를 확인했고 최신 워커에서 캐릭터 변환/VR/복원 후 늦은 완료를 재검증했다.
- 타입·빌드·모듈 검사 통과. 단위/통합 **235개 통과**, Python **14개 통과**. 브라우저 전체 기존31개 중29개 통과 후 워커 갱신으로 실패2개를 재실행 통과. 추가 Delete 키 검사도 통과했다. 전체32개를 한 실행에서 모두 통과했다고 주장하지 않는다.
- 공개 HTTPS에서 실제 복구한 고양이의 개인 상태, History 미리보기, 배치 버튼 활성화를 확인했다. 사용자 장면을 검증 스크립트로 변경하지 않았다.

증거: `history-placement.png`, `image-composition.md`, `texture-uv-repair.md`. 원래 승인 테스트 기록은 변경 전 동작의 역사 자료다.

## 모듈화

자동 등록/공유와 파일 권한은 AssetService, 상태 진행은 FinishingService, 클라이언트별 라이브러리와 씬 명령 판정은 RoomService/도메인이 담당한다. creator/shared의 공개 계약과 표시 조건은 공통 계약 모듈에 있으며 서버에서 다시 강제한다. UI가 도메인 내부를 직접 가져오던 의존 방향 위반은 공통 계약으로 옮겨 해결했다. 원본 파일은 내용 주소로 보존하고 자동 등록이 장면 객체를 생성하지 않는다.

독립 리뷰에서 내부 카탈로그의 오래된 1,000개 제한이 새 에셋의 배치를 막을 수 있음을 발견해 제거했다. History는 최근1,000건을 보여 주며 더 오래된 기록의 탐색 UI는 제공하지 않는다.
