# 생성 진행 표시·정리·프롬프트 — 2026-10-14

## 요청 및 구현

- 이중 클릭 우려: 즉시 ref 잠금, 접수 대기와 진행 중 배너, 닫힌 메뉴 배지, 진행 중 이미지 버튼 비활성화. 오래된 poll 응답이 최근 변경을 덮어쓰지 않도록 순번 검사.
- 대기 취소: 소유자·버전 확인, PostgreSQL 현재 작업 잠금, Redis 단일 Lua에서 queued 판정과 BullMQ 정리 수행, cancelled 상태와 사용 횟수 1회 반환. 실행 중/완료 작업 취소 거부.
- 완성 이미지 숨기기·되살리기·확인 후 삭제. 삭제는 개인 기록/미리보기 접근 제한이며 참조된 저장 파일/3D/장면은 보존. 완료 작업 삭제로 횟수를 환급하지 않음.
- 한국어 입력은 실제 DB/큐에 전달되고 있었지만 SDXL에 원문을 직접 전달했음. Qwen3:4b가 영문 이미지 프롬프트를 준비하도록 작업자 모듈을 분리. 실패 시 명시적 실패, 원문·정리본·모델·버전 기록.

## 재현·수정

취소 중 이전 JOIN 조회가 잠금 대기 후에도 이전 버전 상태를 볼 수 있어 작업이 재등록되는 것을 실제 Redis/DB 회귀로 재현했다. 작업 행을 먼저 잠근 뒤 새 문장으로 최신 버전을 읽는다. PostgreSQL Read Committed 설명: https://www.postgresql.org/docs/14/transaction-iso.html

독립 리뷰에서 queued 확인 후 worker 완료, 그 뒤 remove하는 경쟁을 발견했다. 완료 결과가 사라지는 실패 테스트를 먼저 확인한 뒤 queued 검사와 제거를 한 Redis 스크립트로 합쳐 통과했다. BullMQ6.3.14의 removeJob 스크립트를 재사용하므로 의존 버전 갱신 때 큐 취소 회귀를 반드시 재실행한다.

## 최종 회귀와 후속 무제한 요청

브라우저 전체31개 중30개 통과, 기존 FORBIDDEN 문자열을 기대하던 협업 테스트1개는 앞선 한국어 오류 안내로 기대값을 갱신한 후 단독 재실행 통과. 제품 권한 검사는 유지했다.

후속 사용자 지시로 현재 서버에 DISABLE_GENERATION_LIMIT=1 적용. limit=null 계약/무제한 UI 및 기존 한도0에서도4건 예약 가능한 회귀 테스트 통과. 공개 환경에서 기본3회 한도 수업에 이미지4건 업로드, used4/limitnull, 무제한 표시와 추가 생성 버튼 활성화를 확인했다. 검증 수업만 정리. 기존 한도 숫자나 사용자 사용 기록은 변경하지 않았다.

최종 단위/통합226개 중225개 통과 후, runtime-config 새 필드 기대값1건을 갱신하여 단독 재검증 통과. 제한 없는 서버의 공개 UI/API도 별도로 통과했다.
