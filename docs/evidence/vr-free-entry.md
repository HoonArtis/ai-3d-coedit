# 테스트용 자유 VR 자리 선택

2026-10-14 사용자 요청: VR 모드를 고르면 다른 브라우저에서도 사용 중인 학생 자리를 자유롭게 선택한다. 이름/계정 신설과 기기 연결 코드는 이번 범위에서 제외한다.

## 구현

- Login과 ClassLobby에 작품 만들기/VR 감상 모드. 감상에서는 모든 학생 자리를 선택 가능. 빈 자리는 PC 학생 레코드 없이 임시 감상자와 기본 블록 캐릭터를 사용한다.
- `/lobby/vr`는 열린 수업 초대 코드와 소속 조를 확인한다. 기존 자리는 같은 actor, 빈 자리는 임시 actor의 감상 전용 세션을 발급한다. 세션의 viewer_room_id로 조를 고정한다. 학생 원래 자격 정보와 기존 세션은 바꾸지 않는다.
- `AccountService.resolveRoomToken`은 감상 전용 세션을 기본 거부한다. VR 목록/산출물/감상 방 인증만 명시적으로 허용한다. 편집 방, 생성, 캐릭터 변경, 작품 제출에는 기존 기본 판정을 사용한다.
- App은 서버의 세션 범위에 따라 감상 화면으로 보내며, 새 제출/아바타 변경을 숨긴다. 같은 학생의 기존 아바타를 불러온다.
- 로비 VR 입장은 PC 자리 복귀용 키를 생성하거나 변경하지 않는다.

## 검증·수정

- 신규 통합 테스트 미구현 실패 확인 후 구현. 모든 발급 자리(1~3) 감상 세션, 다른 조 거부, 편집 권한 거부, 닫힌 초대 거부 통과. 실제 배포 확인 시 1조 2번이 빈 자리임을 발견해 빈 자리 임시 감상도 추가하고, 조 제한/편집 거부/학생 자리 미점유 통합 검증을 통과했다.
- 전체 단위/통합 76파일 237테스트 통과 (`npx vitest run --maxWorkers=1`).
- 기존 VR 브라우저 테스트 2개 통과.
- 새 브라우저 E2E 첫 실행에서 로컬 체험 모드가 `/me` 검사를 건너뛰어 감상 UI 분리가 안 되는 회귀 발견. 토큰이 있으면 환경과 무관하게 세션 조회하도록 수정. 재실행 통과.
- 새 E2E: 별도 브라우저의 사용 중인 1~3번 활성화, 2번 선택, 제출본 표시, 원래 actor 유지, 편집/제출/아바타 저장 403, 실제 감상 WebSocket 접속, 루트 주소도 VR 화면 유지.
- 빌드/타입·모듈 경계·장부 검사 수행. Quest 3 실기기 검증은 하지 않았다.

## 모듈화

인증 범위는 AccountService, 공개 수업 입장은 ClassInvites, 감상 허용 지점은 VrBakeService가 담당한다. UI만 비활성화하는 방식에 의존하지 않는다. 기존 작품 편집 공통명령 경로를 변경하지 않는다.
