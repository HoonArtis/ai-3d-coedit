# 텍스처 외형 품질 진단 — 2026-10-14

사용자가 피카츄 뒷면이 무너져 보인다고 보고했다. **워크플로우 누락과 생성 품질 실패를 구분한다.** 단일 입력 이미지 → TripoSG 형상 → MV-Adapter 6방향 이미지 → UV/텍스처 굽기 → 감량은 실제 실행됐다. 하지만 6방향 이미지 중 뒷면이 이미 검게 그려졌고 위/아래 방향에도 심한 번짐이 있다. UV 단계에서 처음 생긴 오류가 아니다.

원본 형상은 60,174면, 크기 약 `[1.904, 1.759, 1.231]`. 텍스처 입력 감량본은 4,900면, 크기 약 `[1.904, 1.758, 1.225]`다. 무채색 기하 확인에서 둥근 몸통/머리의 깊이를 유지한다. 바닥의 작은 분리 조각도 관찰돼 입력 그림의 그림자 제거 품질은 별도 검토 대상이다. 폴리곤 수나 watertight 여부만으로 의미적 외형 품질을 판정하지 않는다.

텍스처 입력에는 한국어 원문이 그대로 전달되고 있었다. 기존 이미지 프롬프트 정리기를 적용한 별도 큐 비교는 74.977초에 완료됐지만 검은 뒷면이 남았다. 정리기가 원문에 없는 빨간 꼬리·풀밭까지 추가했으므로 이 비교는 언어만 바꾼 통제 실험이 아니다. 번역을 적용하면 문제가 해결된다고 주장하거나 이 결과로 사용자 원본을 교체하지 않았다.

## 현재 검사 범위와 빠진 조건

- 검사 중: 작업 상태, 산출물 존재·문맥, GLB/정점·UV 유효성, 폴리곤/텍스처 예산, 권한과 씬 세대.
- 미검사: 여러 시점의 동일 개체·색·무늬 일관성, 뒷면 얼굴 반복, 의미적인 형상 파손, 과도한 텍스처 번짐.
- History의 회전 가능한 3D 미리보기는 제공하지만, 여섯 중간 이미지를 자동 의미 판정하거나 재생성하는 품질 관문은 아직 구현하지 않았다.

추가할 검증은 원인별로 나눠야 한다. UV에 굽기 전 6방향 이미지 일관성을 검사하고, 최종 형상은 무채색/텍스처 표시를 비교한다. 기술적 오류는 실패로, 검증되지 않은 외형 이상은 품질 주의로 구분해야 한다. 자동 판정의 오탐·미탐과 재시도 한도를 실제 불량/정상 사례로 검증하기 전에는 품질 보장으로 표시하지 않는다. 다른 방향의 원본 참고 이미지가 없을 때 모델이 뒷면을 추론한다는 한계도 유지된다.

사용자 원본·비교 GLB·진단 이미지와 상세 로그는 Git 제외 `.cache/pikachu-texture-diagnostic.md` 및 작업 캐시에 보존했다.

## 추가 통제 실험

동일 형상·이미지·seed42에서 프롬프트만 정확히 `Pikachu`로 바꾼 큐 실험도 76.38초에 완료됐지만 검은 뒷면이 유지됐다. 한국어만이 원인이라는 가설은 이 사례에서 지지되지 않았다. 공식 통합과 비교해 중심 정렬되지 않은 바닥 기준 메시, RGBA 전처리를 우회하는 흰 RGB 배경, 512px 입력(공식 768px)이 차이로 확인됐다. 각각 추가 통제 실험이 필요한 후보이며 아직 원인 확정이나 수정 완료가 아니다. 카메라의 이중 -90도처럼 보이는 값은 공식 텍스처 스크립트의 추가 메시 회전과 일치하므로 오류로 단정하지 않는다.
