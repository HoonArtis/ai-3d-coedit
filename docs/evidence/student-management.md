## 작업·검증

1. 계정 삭제 대신 보관 상태, 활성 자리 인덱스, 목록·로그인·입장·발급 인원 계산 적용.
2. 강사 소유 수업 권한 확인, 접속 종료/자리 비우기 API, 편집·VR 접속 레지스트리 분리.
3. 기존 강사 명령 경로로 선택적 배치물 삭제. 파일과 복원 이력 보존.
4. 각 조 카드의 학생 관리 패널, 접속 상태, 기본 작품 유지·명시적 삭제 확인.
5. 리뷰에서 발견한 저장 중 배치 누락, 반복 재접속 후 소켓 잔류를 재현하여 수정.

회귀: `student-management.test.ts`는 타 강사/학생 접근 거부, 접속 종료, 기존 토큰/발급 ID 무효화, 작품 유지/삭제, 새 자리 선택, 두 차례 재접속 후 삭제를 검증한다. `student-removal-race.test.ts`는 저장을 지연시켜 삭제 누락을 실패로 재현 후 통과했다. 브라우저 `student-management.spec.ts`는 목록·접속 종료·삭제 체크박스·빈 자리·장면 삭제를 확인한다.

모듈 경계와 import 순환 검사, 타입 검사와 빌드를 수행한다. 전체 테스트 결과와 공개 환경 확인은 아래에 기록한다.

## 후속 AI 권한 안내 수정

사용자가 보고한 책상 이동 FORBIDDEN은 현재 학생과 책상 소유 계정이 달라 발생했다. 권한은 유지하며 실패 명령의 모델 약속을 먼저 표시하지 않고 서버 결과를 안내하도록 수정했다. 과거 실패 대화도 성공처럼 보이는 요약은 숨긴다. 다른 계정의 물건은 강사가 수정하거나 학생이 자신의 물건을 새로 배치하도록 안내한다. 관련 채팅 테스트 6개, 타입/빌드/모듈 검사 통과.

## 공통 코드 입장 후 생성 메뉴 누락 수정

claim/resume HTTP 응답의 storage 누락으로 학생 생성 패널이 숨겨졌다. 두 응답에 postgres 저장 방식을 포함하고, 이미 저장된 누락 세션은 인증된 room-session API로 갱신한다. 권한/저장 모드를 브라우저에서 임의 추정하지 않는다. 브라우저에서 신규 입장·이전 세션 복구·자리 복귀 모두 생성 메뉴 표시를 검증했다. 생성 업로드/재질 실패 경로 회귀 통과(업로드 첫 실행은 Chromium ERR_NO_BUFFER_SPACE로 페이지 진입 실패, 재실행 통과). 타입·빌드·모듈 검사 통과. 공개 HTTPS에서 별도 임시 수업으로 메뉴 표시·펼침·기존 세션 복구를 확인하고 검증 수업만 정리했다.
