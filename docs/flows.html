AI 공간 꾸미기 흐름도

학생 요청이 씬 변경이나 3D 에셋이 되기까지의 두 경로입니다. 코드 기준은 feat/implementation 브랜치 a1d8a18(2026-10-14)입니다. 보라색 PROMPT는 모델(Qwen·SDXL·MV-Adapter)에 문장이 들어가는 자리이며 고도화할 때 손볼 지점입니다. 회색 "규칙"은 모델 없이 코드로 판정하는 자리입니다.

두 흐름이 만나는 곳

generate챗봇이 고른 문장이 B의 2단계(필터)부터 그대로 들어감. 생성 op는 다른 편집과 섞을 수 없음.
retexture챗봇의 prompt 인자 + 기존 형상 → 텍스트 조건 MV-Adapter(50 step). 이미지 단계는 건너뜀.
placeHistory의 완성 에셋을 씬에 놓을 때. 기즈모, 챗봇, 강사 모두 같은 명령 형식.

고도화 후보

1

텍스처 단계에 한국어 원문이 들어감10/15 수정

B-6은 정리된 영문이 아니라 학생 원문(row.source.prompt)을 MV-Adapter에 넘깁니다. retexture도 챗봇 인자를 그대로 씁니다. MV-Adapter는 SDXL 계열이라 영어를 전제로 합니다. 피카츄 뒷면 오류와 관련이 있을 수 있으며, 서버 PC의 prompt.json과 텍스처 결과를 비교해 확정합니다. 10/15: GPU 워커가 텍스처 직전에 같은 정리기로 영어 문장을 다시 만들어 넘기도록 바꿨습니다(prepareTexturePrompt, 결과 metadata.texturePrompt).

2

챗봇이 직전에 실행한 내용을 모름

A-2의 대화 이력에는 summary만 남고 실제 ops와 결과는 빠집니다. "방금 놓은 거 옮겨" 같은 이어지는 요청에 약할 수 있습니다.

3

챗봇에 생성 문장 작성 안내가 없음

generate 도구 설명은 한 줄입니다. 챗봇이 만든 문장은 B-3의 정리 단계를 다시 거칩니다.

4

씬 전체를 매 요청에 넣음

A-3은 씬과 라이브러리를 통째로 JSON으로 넣습니다. 물건이 200개까지 늘면 16k 컨텍스트가 부담될 수 있습니다.
