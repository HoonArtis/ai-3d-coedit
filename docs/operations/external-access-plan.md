## 작업 파일 지도

기존 파일을 먼저 확인하며, 파일명은 구현 시 실제 구조에 맞춰 유지한다.

- `apps/web/src/accounts/api.ts`, `generation/GenerationPanel.tsx`, `editor/room-transport.ts`: 분산된 서버 주소 사용처. 공통 주소 결정 모듈로 정리할 후보.
- `apps/web/vite.config.ts`: 현재 개발 설정. 개발 서버 자체를 그대로 공개할지 가정하지 말고 빌드된 화면 제공 방식을 정한다.
- `apps/server/src/main.ts`, `dev.ts`, `runtime.ts`, `server.ts`: 인증/미리보기 진입점, origin 및 로컬 리스닝.
- `apps/server/src/accounts/routes.ts`: 강사 등록·로그인 경계.
- `packages/jobs/src/queues.ts`: GPU 1, LLM 2, CPU 2의 현재 제한. 근거 없이 변경하지 않는다.
- `tools/acceptance-https.ts`: 기존 HTTPS/WSS·서버 재시작 시험 참고. 테스트 인증서와 지원 플래그 스텁을 외부 운영 설정으로 복사하지 않는다.
- 신규 후보 `tools/serve-external.ts`: 빌드된 웹 파일, API, WS를 한 로컬 포트로 전달하는 진입점. 기존 기능과 중복되면 기존 서버 통합을 우선 검토한다.
- 신규 후보 `tests/e2e/external-access.spec.ts`: 외부 주소·인증·소켓·재접속 검증.
- 신규 기록 `docs/evidence/external-access.md`: 조건, 인원, 측정값, 실패/수정/재검증 결과.

## 아침 실행 티켓

각 티켓은 준비 → 검증 → 최소 수정 → 재검증 → 모듈화 검토 → 증거 기록 순서로 끝낸다.
아래 체크는 현재 모두 미완료다. 기존 구현 완료 장부를 이 계획만으로 변경하지 않는다.

### EXT-01 — 현재 실행 상태와 데이터 보호

- [ ] 작업 폴더/브랜치/미커밋 변경과 프로젝트 지침을 확인한다. 기존 변경을 덮어쓰지 않는다.
- [ ] 서버·웹·LLM·GPU·CPU·Docker가 실제 살아 있는지 확인한다. 과거 세션 번호를 현재 상태로 간주하지 않는다.
- [ ] 기존 작품과 DB 보존 상태를 확인하고, 별도 테스트 수업·계정을 준비한다.
- [ ] 포트 충돌 없이 로컬 로그인·편집·AI 요청이 동작하는지 확인한다.
- 완료 조건: 현재 실행 경로와 저장 위치가 기록되고 로컬 기준 동작이 확인됨.

### EXT-02 — 공개 접속 전 인증 경계

- [ ] 기존 계정/권한 테스트를 확인하고 익명 세션 거부·신규 강사 등록 제한의 검증 사례를 추가한다.
- [ ] 인증 모드 진입점으로 외부 테스트 서버를 준비한다. 기존 로컬 미리보기와 구분한다.
- [ ] 지정 테스트 사용자만 입장하도록 필요한 최소 변경을 한다.
- [ ] 타 방 접근·타 학생 물체 변경·무인증 생성 거부를 검증한다.
- 완료 조건: 공개할 서버에 익명 우회 경로가 없고 테스트 계정 권한이 의도대로 작동함.

### EXT-03 — 단일 주소 제공과 실시간 연결

- [ ] 화면·API·WS의 주소 결정 규칙을 정하고 관련 회귀 테스트를 추가한다.

- [ ] 로컬에서 로그인→방 입장→2인 편집→업로드→생성 결과 다운로드를 검증한다.
- [ ] `npm run typecheck`, `npm run check:modules`, 변경 관련 테스트, `npm run build`를 확인한다.
- 완료 조건: 브라우저가 하나의 주소로 전체 흐름을 수행하고 WS가 실제 연결됨.

### EXT-04 — HTTPS 임시 링크와 외부 2인 확인

- [ ] Cloudflare Tunnel 설치 여부와 현재 공식 제한을 확인한다. 초기 시험은 임시 링크를 사용한다.
- [ ] EXT-02/03 통과 후 웹/API용 단일 진입점만 터널에 연결한다. DB/Redis/Ollama는 공개하지 않는다.
- [ ] 생성된 실제 주소를 허용 origin에 반영하고 HTTPS/WSS 인증서·연결을 확인한다.
- [ ] 휴대전화 모바일 데이터 또는 다른 장소의 PC에서 실제 접속한다. 동일 PC의 두 탭 시험을 외부망 검증으로 쓰지 않는다.
- [ ] 2명의 로그인·동일 방 이동 동기화·새로고침·다운로드·업로드를 확인한다.
- 완료 조건: 실제 외부망 성공 증거와 현재 유효한 링크를 기록함. 외부 기기가 없으면 이 항목은 미검증으로 남김.

### EXT-05 — 5명 혼합 사용

- [ ] 편집만 사용하는 기준 구간을 측정한다.
- [ ] 편집 중 AI 요청과 생성 요청을 추가해 혼합 부하를 측정한다.
- [ ] GPU 메모리, CPU/RAM, 업로드 속도, 대기 시간, 실패율을 기록한다.
- [ ] 단절/새로고침/중복 클릭/강사 복원과 늦은 결과를 시험한다.
- [ ] 발견한 결함마다 재현 사례→최소 수정→동일 사례 재검증을 남긴다.
- 완료 조건: 데이터 유실·중복 차감·권한 누수 없이 회복하며, 실제 대기 시간을 사용자에게 설명할 수 있음.

### EXT-06 — 15명·30명 확대와 운영 판단

- [ ] 5명 결과를 보고 편집 지연·AI 대기·실패율의 허용 기준을 정해 기록한다.
- [ ] 15명에서 같은 시험을 수행하고 기준을 통과하면 30명으로 늘린다.
- [ ] 실제 사람/브라우저/자동 소켓의 수와 동시 생성 요청 수를 구분해 기록한다.
- [ ] 서버 재시작 후 저장 작품과 작업 상태를 확인한다. 임시 시험 데이터만 정리한다.
- [ ] 안정적으로 통과한 인원과 아직 미검증인 인원을 구분해 최종 문서에 반영한다.
- 완료 조건: 측정에 근거한 권장 접속 인원이 정해짐. 30명을 못 채우면 실제 시험한 범위까지만 결론을 낸다.
