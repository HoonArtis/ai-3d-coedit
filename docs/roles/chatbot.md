# 역할: AI 챗봇

맡는 것: 학생별 챗봇(LLM 워커), MD 시스템 프롬프트, 도구 정의, 배치 알고리즘, 대화 로그.

현재 구조와 고도화 이력(두 단계 분류, 결정적 검사, 평가 방법): [../chatbot-improvement.md](../chatbot-improvement.md).

## 두뇌 분담

LLM은 도구 이름과 인자만 고른다. 좌표 계산과 겹침 검사는 배치 알고리즘 코드가 한다. 같은 입력이면 같은 결과가 나와야 한다. 그래서 소형 로컬 모델로도 돌아간다.

## 할 일

1. **도구 정의 (3일차)**: `../command-api.md`의 op를 그대로 도구로 만든다. 도구 설명에는 언제 쓰는지와 예시 문장 2~3개를 넣는다.
2. **배치 알고리즘**: `arrange_around`, `align_row`, `distribute`, `scatter`, `place_on`, `face_toward`. 바닥·겹침 검사 포함.
   - 완료: "탁자 주위에 의자 4개"가 명령 1건(트랜잭션)으로 실행되고, 되돌리기 1번에 모두 사라진다.
3. **MD 시스템 프롬프트**: 아래 다섯 부분으로 쓴다.
   1. 역할과 말투: 고등학생 대상, 짧고 친절하게, 실행 전 무엇을 할지 한 줄 요약
   2. 도구 목록과 예시
   3. `describe_scene` 결과(이름·소유자·위치·크기) 읽는 법
   4. 모호할 때: "저거", "여기"는 현재 선택·카메라 중심 기준. 그래도 모호하면 한 번만 되묻기
   5. 지킬 선: 자기 에셋만 조작, 생성 요청은 필터 통과분만, 상한 안에서
4. **모델 선정**: 로컬 우선. 후보는 도구 호출을 지원하는 공개 모델(예: Qwen3 계열, gpt-oss-20b). 라이선스는 `../licenses.md`에 기록. 클라우드 차선은 2026-10-15 제거, 로컬만 쓴다.
   - 완료: 대표 요청 20개 시험에서 도구·인자 선택 성공률을 기록하고, 로컬과 클라우드 중 하나를 고른다.
5. **큐와 로그**: LLM 요청은 동시 처리 수 제한 큐를 거친다(학생 30명 대비). 대화 전문·호출 명령·결과를 저장해 강사가 열람한다.

## 경계

- 챗봇은 그 학생의 권한으로만 명령을 보낸다. 판정은 방 서버가 한다.
- 생성 요청은 `generate` 명령으로 큐에 넣는다. 파이프라인 내부는 `generation-gpu.md`.
- 미성년자 대상: 부적절 생성 요청 필터, 강사 승인, 대화 로그.
