# 역할: 강사 기능 · 계정

맡는 것: 강사 계정, 학생 계정 일괄 발급, 방 코드 입장, 강사 대시보드, 생성물 승인함, 대화 로그 열람, 복원 UI, 생성 횟수 설정. 화면 시안은 `index.html` 3장.

## 할 일

1. **계정 (4일차)**: 이메일 가입 없이 강사가 학생 계정을 일괄 생성한다(미성년자 개인정보 최소화). 학생은 방 코드 + 발급 ID로 입장한다. 작품은 계정에 귀속되어 저장된다.
   - 완료: 강사가 30명분 계정과 방 6개를 만들고, 학생이 ID로 자기 조 방에 들어간다.
2. **대시보드**: 조별 방 썸네일, 인원, 승인 대기 배지. 썸네일을 누르면 그 방에 강사로 입장한다.
3. **승인함**: 생성물 승인·거절. 승인된 것만 수업 공유 라이브러리에 공개.
4. **대화 로그**: 학생별 챗봇 대화 전문과 호출 명령 열람.
5. **설정**: 수업당 1인 생성 횟수.
6. **복원 UI (7일차)**: 에셋 변경 이력 보기, 에셋 단위 복원, 방 스냅샷 복원. 규칙은 `room-server.md`의 예상 버그 표.

## 경계

- 강사도 씬 변경은 `../command-api.md`의 명령(source: teacher)으로만 한다.
- 판매 모델(결제·좌석·크레딧)은 보류. 계정 구조는 나중에 좌석 수를 붙일 수 있게 수업 단위로 둔다.

## 후속 변경: 공통 수업 코드와 로비

2026-10-14 사용자 선택: 강사 로그인 → 클래스룸 생성 → 공통 초대 코드 공유 → 학생이 조/빈 자리 선택 → 편집실 입장. 기존 방 코드+개인 ID는 유지한다. 자리 예약과 기존 일괄 발급은 같은 수업 잠금으로 직렬화한다. 복귀 키는 브라우저에만 보관하며 서버에는 해시를 저장한다. 공통 코드를 안다고 사용 중인 자리에 들어갈 수는 없다. 신규 입장을 닫아도 기존 학생의 복귀는 유지한다. 브라우저 데이터 삭제/기기 이전 복구는 별도 기능이다.
