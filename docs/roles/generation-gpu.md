# 역할: 생성 파이프라인 · GPU 워커

맡는 것: Redis + BullMQ 작업 큐, 이미지 모델, 배경 제거, TripoSG, 텍스처, 감량, 강사 승인 연결, 캐릭터 업로드 변환, VR 굽기 작업 실행.

## 파이프라인

글 또는 그림 → 이미지 모델(글일 때만) → **학생 확인** → 배경 제거 → TripoSG 형상 → MV-Adapter 텍스처 → 감량(약 1만 삼각형, GLB) → 강사 승인 → 수업 공유 라이브러리 → 방에 배치

## 할 일

1. **큐 골격 (4일차)**: 단계별 작업을 큐로 연결. GPU 1장 기준 형상·텍스처는 동시 1개. 진행 단계와 대기 순번을 클라이언트로 알린다.
2. **이미지 모델 + 확인 단계 (5일차)**: 글이면 이미지를 만들어 학생에게 보여 주고 확인을 받은 뒤에만 3D로 넘어간다. 그림 업로드는 바로 확인 단계로.
3. **TripoSG + 텍스처 + 감량**
   - 완료: 글 한 줄로 텍스처 입힌 GLB가 방에 배치되고, 단계별 소요 시간을 실측해 기록한다(데모 기준 추정 1~3분).
4. **결과 검증**: 결과를 "방 + 스냅샷 세대 번호"로 확인하고, 세대가 다르면 라이브러리에만 넣는다(예상 버그 #4).
5. **캐릭터 업로드 (7일차)**: 믹사모 FBX → GLB 변환, 감량, 뼈대·애니메이션 유지 확인. 실패하면 기본 아바타로 대체.
6. **VR 굽기 작업**: `webxr.md`가 정한 변환을 큐 작업으로 실행.

## 판매 차단 의존물

- **RMBG-1.4**: TripoSG 공식 추론 스크립트가 배경 제거용으로 자동으로 내려받는다. 비상업 전용.
- **nvdiffrast**: MV-Adapter 텍스처 렌더링이 의존한다. 연구·평가 전용.
- 테스트에서는 그대로 쓰되, 교체 후보와 진행 상황을 `../licenses.md`에 남긴다. 텍스처가 끝내 대체되지 않으면 차선책은 미리 만든 재질 프리셋(나무·금속·천 등) 중 AI가 골라 입히기(즉시 적용, 물체당 재질 1개).
- Hunyuan3D 계열은 한국 제외 라이선스라 후보에서 뺀다.

## 경계

- 생성 횟수 제한(수업당 1인 N회)은 강사 설정값을 따른다.
- 감량 수치는 `../budgets.md`가 원본.
- 1주 일정에서 5일차가 최대 위험(GPU 설치·VRAM·의존물 충돌)이다. 막히면 즉시 보고하고 텍스처를 차선책으로 내린다.
