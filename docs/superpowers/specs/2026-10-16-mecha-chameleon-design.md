# 메차카멜레온 숨바꼭질 설계

작성 2026-10-16 · 상태: 확정(사용자 승인) · 대상: ai-3d-coedit `feat/implementation`

## 1. 한 줄 요약

5인 1조로 꾸민 맵을 무대로, 조원이 회색 마네킹을 칠하고 자세를 잡아 자기 조 맵 에셋 사이에 숨는다. 숨은 뒤에는 각자 상대 조 맵에 술래로 들어가 블록 코딩으로 만든 총으로 찾는다. 내 몸이 먼저 발견되면 술래 중이어도 탈락하여 고스트로 구경한다.

## 2. 확정 규칙

| 항목 | 결정 |
|---|---|
| 대진 | 2개 조 맞대결. 판마다 상대를 바꾸는 순환(라운드 로빈). 홀수 조면 판마다 1조 휴식(고스트 관전) |
| 판 종료 | 한 조 전원 발견 시 즉시 종료. 제한 시간 종료 시 생존 인원 많은 조 승리, 같으면 무승부 |
| 찾기 | 술래 총 발사. 서버가 명중 판정 |
| 찾기 HP | 기본 10. 헛발 -1, 발견 시 가득 찬 상태로 리셋 |
| HP 0 | 찾기 자격만 상실하고 관전. 숨은 몸은 생존 유지(생존 인원 포함) |
| 발견됨 | 술래 진행 중이어도 즉시 탈락 → 고스트 |
| 숨기 준비 | PC 편집 화면. 마네킹 자세 선택 → 마우스 색칠 → 배치 |
| 찾기 플랫폼 | VR 헤드셋(컨트롤러 이동) + PC 1인칭 혼합. 같은 판에 섞여 참여 |
| 기본 시간 | 숨기 준비 7분, 대결 5분, 다음 판 재숨기 2분. 강사가 변경 가능 |
| 기록 | 서버가 경기 이벤트 전부를 로그로 남김 |

헤드셋은 수업당 4대 기준(CLAUDE.md)이므로 한 판 10명 중 다수는 PC 1인칭으로 참여한다고 가정한다.

## 3. 구조: 게임 전용 방 (A안)

기존 편집 방(`colyseus-room.ts`)과 VR 감상 방(`vr/viewing-room.ts`)은 건드리지 않고 **숨바꼭질 방**을 새로 만든다.

- 맵은 각 조의 **최신 제출본 + VR 굽기 결과**를 그대로 쓴다. 판 동안 맵은 고정된다.
- VR 입장, 아바타, 포즈 동기화(`vrPoseSchema`, 100ms 방송)는 감상 방 코드를 공용 모듈로 뽑아 재사용한다.
- 판 진행(준비 → 대결 → 결과), HP, 명중 판정, 생존 집계는 전부 서버 권한으로 처리한다.
- 숨은 몸(마네킹)은 장면 명령(`{actor, source, requestId, ops[]}`)이 아닌 **경기 상태**로 저장한다. 제출본과 편집 중인 장면은 바꾸지 않으므로 CLAUDE.md의 "명령 1건" 규칙과 충돌하지 않는다. 숨기 준비 화면은 기존 위치·방향·크기 도구 UI를 재사용하되 결과는 경기 관리 서비스로 보낸다.

새 단위(각자 독립 테스트 가능):

| 단위 | 위치(예정) | 하는 일 |
|---|---|---|
| 경기 규칙 | `packages/domain/src/hide-game/` | 순수 함수: 대진 생성, 단계 전환, HP 계산, 승패 판정. 네트워크 없음 |
| 경기 계약 | `packages/contracts` | 메시지·저장 스키마(zod): 숨은 몸, 발사 요청, 판정 결과, 로그 이벤트 |
| 숨바꼭질 방 | `apps/server/src/hide-game/` | 콜리세우스 방. 맵별 1개(그 맵의 숨은 몸 + 상대 술래 + 고스트) |
| 경기 관리 | `apps/server/src/hide-game/match-service.ts` | 강사 명령, 대진·판 타이머, 맵 고정, 로그 저장 |
| 숨기 준비 UI | `apps/web/src/hide-game/prepare/` | 편집 화면 "숨기" 탭: 자세·색칠·배치 |
| 찾기 UI | `apps/web/src/hide-game/seek/` | VR·PC 1인칭 이동, 총, 고스트 |
| 총 코딩 UI | `apps/web/src/hide-game/gun-lab/` | Blockly, 코드 보기, 시험 사격장 |
| 강사 UI | `apps/web/src/accounts/` 확장 | 경기 만들기, 대진표, 진행, 로그 |

## 4. 경기 흐름

0. **경기 열기(강사)**: 참가 조 선택, 시간·HP 설정 → 순환 대진 자동 생성(4조 = 3판).
1. **숨기 준비(PC)**: 경기 생성 순간 각 조 최신 제출본으로 맵 고정(이후 편집은 경기 맵에 반영되지 않으므로 편집 잠금 불필요). 각자 마네킹 1개를 자세 선택·색칠·배치. 조원끼리 위치 보임, 상대는 볼 수 없음. 시간 종료 시 숨은 몸(자세, 위치·방향·크기, 색칠 이미지) 서버 고정. 미배치자는 시작 지점 근처에 회색으로 자동 배치.
2. **대결(VR/PC)**: 상대 맵 시작 지점에 등장. 같은 조 술래끼리 아바타 보임. 발견 시 피발견자 즉시 고스트, 마네킹은 "발견" 표시.
3. **결과 → 다음 판**: 승패·생존 인원·발견 기록 표시. 다음 판은 새 상대라 위치 유지가 기본, 재숨기 2분 제공. 마지막 판 뒤 조별 승수 집계.

## 5. 찾기 판정(서버)

발사 요청 `{origin, direction, hitTargetId, hitPoint, seq}`:

1. 학생 화면이 실제 메시 기준으로 광선을 쏘아 첫 대상을 보낸다(가림 계산은 화면 담당).
2. 서버 확인: 대상이 이 맵의 생존 마네킹인가 / 거리 ≤ 10m / `origin`이 최근 포즈와 1m 이내 / 직전 발사 후 0.5초 이상 / 발사자가 HP > 0인 생존 술래인가.
3. 명중 → 대상 탈락, 발사자 HP 리셋. 헛발(에셋·빈 곳) → HP -1. HP 0 → 관전.
4. 동시 요청은 서버 도착 순서로 처리.

알려진 한계: 가림 판정은 학생 화면을 신뢰한다. 조작된 앱은 벽 너머를 맞힐 수 있다. 수업 용도에서는 수용하고, 필요 시 서버 메시 레이캐스트로 강화한다.

이동: VR은 왼쪽 스틱 걷기 + 오른쪽 스틱 스냅 회전, 게임 중 텔레포트 끔. PC는 WASD + 마우스(포인터 잠금). 공통으로 맵 경계 제한, 에셋 상자 충돌로 통과 금지.

## 6. 술래 총과 블록 코딩

**총 모델**: HideInAI(Unity) `Sci-fi Pistol/anyma` 권총을 GLB로 변환해 사용. 에셋스토어 유료 에셋 추정이므로 `docs/licenses.md` 점검 목록에 추가한다.

**블록 분류**(HideInAI `PistolMecanic.cs` 기준):

| 분류 | 블록 | 원본 |
|---|---|---|
| 이벤트 | 트리거를 당겼을 때(임계 0.6, 반자동) | `Update` |
| 조건 | 쿨타임이 끝났으면 / 맞힌 게 사람이면 | `rpm`, `delay`, `Ballistics` 분기 |
| 동작 | 광선 쏘기(사거리), 소리 재생, 총구 불꽃, 맞은 자리 효과, 탄피 배출, 컨트롤러 진동 | `Ballistics`, `Shoot`, `SpawnHitEffect`, `EjectShell`, `PlayRightHandShootHaptic` |
| 값 | 쿨타임, 사거리, 불꽃 크기, 탄피 힘, 진동 세기 | SerializeField 값 |

**총 만들기 화면(PC "술래 총" 탭)**:

- 블록 판: 기본 총이 거의 조립된 상태로 시작, 미션 3~5단계로 빈칸 채우기. 완료 뒤 준비된 블록 자유 조합.
- 코드 보기: 블록 → JavaScript 실시간 표시, 블록 선택 시 해당 줄 강조. 코드 안 숫자는 허용 범위 안에서 직접 수정 가능, 블록과 양방향 반영. 자유 타이핑 금지.
- 시험 사격장: 마네킹 과녁·상자가 있는 연습 공간. 실제 게임과 같은 규칙으로 맞힘/헛발/HP 표시.
- 저장: 학생별 총 정의(블록 XML/JSON) 저장, 게임과 VR에 그대로 사용.

**공정성 경계**: 블록 코드는 학생 화면에서 연출과 범위 제한 값만 바꾼다(쿨타임 ≥ 0.5초, 사거리 ≤ 10m). HP·판정·최소 간격은 서버 규칙이 우선한다. 미션 미완료 학생은 기본 총으로 참여한다. 블록 실행은 정해진 블록 함수만 호출하는 해석기로 돌리고 `eval`을 쓰지 않는다.

## 7. 마네킹·자세·색칠

- 회색 리깅 마네킹 1종, 자세 10개(서기, 차렷, 웅크리기, 엎드리기, 눕기, 의자 앉기, 벽 기대기, 팔 벌리기, 무릎 꿇기, 공처럼 말기). 자세는 고정 포즈 데이터로 저장하고 명중 판정용 단순 충돌체를 자세별로 둔다.
- 색칠 창: 마우스로 메시에 직접 칠하기(UV 512×512). 붓 3단계, 색 선택, 스포이트(맵 화면에서 찍기), 지우개, 전체 채우기.
- 배치: 기존 위치·방향·크기 도구 재사용. 크기 0.8~1.2배 제한. 몸 절반 이상이 에셋 밖에 있어야 저장.
- 조원 마네킹은 반투명 테두리로 표시.

## 8. 고스트와 강사

- **고스트**(탈락, 휴식 조): 반투명, 벽 통과 자유 비행, 모든 맵 이동, 숨은 위치 전부 보임. 생존자에게 보이지 않고 소리 없음.
- **HP 0 관전자**: 고스트처럼 구경하되 자기 조 맵 입장 불가(훈수 방지).
- **강사**: 경기 만들기, 대진표, 판 시작·일시정지·강제 종료, 시간·HP 설정, 조별 생존·남은 시간·발견 알림, 판 종료 후 로그(발견 순서, 발사 기록, 학생별 명중률), 학생 총 블록 열람.

## 9. 서버 로그

경기 이벤트를 시간순으로 저장(PostgreSQL 테이블, 경기 ID 기준): 경기 생성, 단계 전환, 숨은 몸 고정, 발사(발사자, 위치·방향, 대상, 결과, HP 변화), 발견, HP 0, 접속·재접속, 판 종료·결과. 강사 화면에서 조회한다.

## 10. 오류·예외 처리

- 접속 끊김: 15초 재접속 허용(감상 방과 동일). 끊긴 동안 숨은 몸은 그대로 유지, 술래 자격은 재접속 시 복구.
- 제출본 없는 조: 경기 참가 조 선택 단계에서 막고 "제출 먼저" 안내.
- 숨기 준비 중 강사 일시정지: 타이머 정지, 편집 계속 허용 안 함.
- 정원: 기존 방당 5명 규칙과 별개로 숨바꼭질 방은 상대 술래 5 + 고스트 최대 전원을 수용.

## 11. 만들 순서

| 순서 | 묶음 | 완료 기준 |
|---|---|---|
| 1 | 게임 뼈대: 숨바꼭질 방, 판 진행, 서버 판정, HP, 로그, 기본 총(클릭/트리거), 고스트, 강사 시작 | 회색 마네킹으로 숨기·찾기 전체가 PC 2창 + VR 1창 혼합으로 끝까지 진행 |
| 2 | 마네킹 꾸미기: 자세 10개, 마우스 색칠, 스포이트 | 색칠한 마네킹이 상대 화면에 같은 모습으로 보임 |
| 3 | 블록 코딩 총: Blockly, 코드 보기, 미션, 시험 사격장, 권총 모델 | 미션 완료한 총으로 게임 참여, 서버 제한 유지 |

각 묶음은 별도 구현 계획(writing-plans)으로 진행한다. 이번 계획은 1번부터.

## 12. 시험

- 경기 규칙 순수 함수: 대진(짝수·홀수 조), HP 증감·리셋, 승패·무승부, 단계 전환 단위 테스트(vitest).
- 판정: 거리 초과, 위치 위조, 연타, HP 0 발사, 이미 탈락한 대상, 동시 발견 테스트.
- 통합: Playwright로 PC 2창 이상 접속, 숨기 → 대결 → 결과 → 다음 판 끝까지 진행. 로그 이벤트 개수 확인.
- VR: 기존 소프트웨어 웹VR 검증 방식 + 사용자 확인 헤드셋 접속.
