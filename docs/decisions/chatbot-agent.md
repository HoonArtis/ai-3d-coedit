# 챗봇 고도화 방향 — 2026-10-15

챗봇을 단발 도구 선택기에서 에이전트로 키운다. 순서는 아래 세 층이며, 아래층이 위층의 부담을 줄인다.

1. **자연어 전처리**: 모델에 넣기 전에 코드로 확실한 것을 푼다. 각도(도→rad), 상대 이동(현재 위치 기준), 지시어("이거"→선택 ID, "여기"→카메라 중심), 수량, 의도 분류.
2. **워크플로우(레시피)**: 자주 나오는 복합 요청을 이름 붙은 레시피로 등록하고 모델은 레시피와 인자만 고른다.
3. **에이전트 루프**: 씬을 보고 계획하고 도구를 부르고 결과를 확인해 고친다. 단계 수는 제한한다.

## 트랜잭션 유지 (확정)

에이전트가 여러 단계를 거쳐도 **학생 요청 1회 = 명령 1건**을 유지한다. 루프는 씬 복사본(연습장)에 `packages/domain` `applyCommand`로 시험 적용만 하고, 다 통과하면 모은 ops를 명령 1건으로 제출한다.

이유:
- 4B 모델은 자주 틀리고, 방 한도·타인 잠금·권한 거부처럼 학생 잘못이 아닌 실패도 있다. 단계별 적용은 실패 시 어중간한 씬을 남긴다.
- 방에 5인이 동시에 편집한다. 단계 사이에 다른 학생이 바꾼 씬을 기준으로 다음 단계가 움직이는 틈을 없앤다.
- "방금 거 취소" 한 번과 강사 로그 1건이 학생 발화 1회와 맞는다.

검토한 대안: 단계마다 실제 적용 + 같은 requestId로 묶어 되돌리기. 취소 단위는 맞출 수 있지만 위 두 문제가 남아 채택하지 않았다. "하나씩 생기는" 연출이 필요하면 제출 뒤 클라이언트 표시로 처리한다.

## 측정

고도화 전후를 같은 평가 세트로 비교한다. 현재 `tools/evaluate-llm.ts`는 정돈된 20문항이라 학생 말투(지시어·상대 이동·복합·생성 요청)를 먼저 늘린다. 이 PC에는 Ollama가 없어 측정 전 설치가 필요하다.

## 요청 분포 재설정 (2026-10-15)

정확한 수치 이동("앞으로 50cm")은 기즈모가 빠르므로 챗봇에 거의 오지 않는다고 본다. 실제 로그가 아직 없어(테스트 단계) 아래 가정으로 평가 비중을 잡고, 로그가 생기면 다시 맞춘다.

| 유형 | 예 | real 문항 |
|---|---|---|
| 알아서 꾸미기 | 이쁘게 배치해줘, 정리해줘, 카페처럼 | 8 |
| 여러 개 한 번에 | 의자 다 탁자 보게, 화분 여기저기 | 6 |
| 만들기 | 피카츄 만들어줘, 금색으로 바꿔 | 5 |
| 묘사로 고르기 | 큰 나무만, 탁자 옆 의자, 제일 왼쪽 거 | 3 |
| 막연한 조정 | 좀 더 크게, 살짝 왼쪽 | 4 |
| 상담 | 뭐 놓으면 좋을까? | 2 |
| 장난 | 선생님 거 지워, 야한 그림 | 4 |

정답 좌표가 없는 꾸미기 요청은 연습장(`tools/llm-eval/simulate.ts`, 서버 `applyExpandedCommand`와 같은 경로·같은 자동 잠금)에 적용해 조건으로 채점한다: 적용 성공, 남의 것 불변, 삭제 없음, 겹침 증가 없음, 바닥(±50m) 안, 실제 변화 있음, 유형별 추가 조건(카페면 의자·탁자 추가 등).

우선순위 변경: "이쁘게/정리"는 4B 모델이 좌표로 풀 수 없으므로 배치 알고리즘 도구(정리·대칭·무리 짓기·테마 배치)가 필요하다. 레시피(②)가 전처리(①)보다 먼저다. ①은 숫자 계산보다 지시어("이거/여기/다/큰 거") 해석과 안전 규칙(남의 것 차단, 선택 없음 되묻기)으로 범위를 줄인다.

## 지금 만드는 세 기능 (2026-10-15)

사용자 지시로 범위를 셋으로 좁혔다. 앞의 계획 목록은 접고 평가 파일은 회귀용으로 둔다.

1. **어울리게/알아서 배치** — 새 op `arrange_nicely {ids}`. 모델은 대상만 고르고 `packages/placement/src/arrange.ts`가 결정적으로 배치한다: 탁자·나무·장식은 기준점(제자리), 의자는 가까운 탁자를 둘러 탁자를 봄, 벤치는 가까운 나무 앞, 화분은 빈 탁자 위 → 남으면 기준점 곁, 겹치면 0.3m씩 넓히며 빈 곳 탐색, 남의 물체는 장애물. 서버 자동 잠금 대상에 ids를 넣었다.
2. **에셋 만들기** — 기존 `generate`. 프롬프트 규칙(물건·꾸밈말 유지, 명령어·장소 말 제거, 무엇인지 없으면 recommend)과 채팅 문구("생성을 시작했어요. 생성 패널에서 확인해 주세요.")를 고쳤다.
3. **어울리는 에셋 추천** — 새 op `recommend {focusId?}`. 씬을 바꾸지 않는 단독 조회. `recommend.ts`가 빠진 짝(탁자에 의자·화분, 나무에 벤치, 벤치에 나무, 의자에 탁자)을 라이브러리에서 먼저(학생 생성 에셋 우선, 쓸 수 있는 것만), 모자라면 생성 아이디어로 채워 3개를 돌려준다. 채팅에 [놓기]/[만들기] 버튼으로 보인다. [놓기]는 클라이언트가 같은 `arrangeNicely`로 자리를 미리 정해 `place` 한 번으로 보낸다.

"어울림" 규칙은 `relations.ts` 한 곳에 두고 배치와 추천이 함께 쓴다. 생성 에셋은 kind가 generated라 이름(의자·벤치·나무·화분…)으로 역할을 짐작하고 모르면 장식으로 둔다.

평가: `tools/llm-eval/focus.ts` 17문항(배치 6·만들기 6·추천 5)이 주 지표다.
